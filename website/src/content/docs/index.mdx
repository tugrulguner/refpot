## Try a reservation rule

This room can hold 10 people. A maintained view stores the number of reserved seats, and an assertion requires the database to stay within capacity at commit. The first booking reserves six seats; the next tries to reserve five more.

Save as `reservations.py`:

```python
from refpot.sql import Database, SQLError

with Database() as db:
    db.execute(
        "CREATE TABLE bookings (id INTEGER PRIMARY KEY, "
        "room INTEGER NOT NULL, seats INTEGER NOT NULL)"
    )
    db.execute(
        "CREATE MATERIALIZED VIEW usage AS "
        "SELECT room, SUM(seats) AS seats FROM bookings GROUP BY room"
    )
    db.execute(
        "CREATE MATERIALIZED VIEW over_capacity AS "
        "SELECT room FROM usage WHERE seats > 10"
    )
    db.execute("CREATE ASSERTION capacity CHECK (NOT EXISTS (SELECT * FROM over_capacity))")

    db.execute("INSERT INTO bookings VALUES (1, 1, 6)")
    try:
        with db.transaction():
            db.execute("INSERT INTO bookings VALUES (2, 1, 5)")
            assert db.execute("SELECT seats FROM usage WHERE room = 1").rows == ((11,),)
    except SQLError:
        print("Booking rejected: capacity is 10")
    else:
        raise AssertionError("Expected the capacity rule to reject the commit")

    total = db.execute("SELECT seats FROM usage WHERE room = 1").rows[0][0]
    assert total == 6
    print(f"Reserved seats: {total}")
```

```sh
python reservations.py
```

```text
Booking rejected: capacity is 10
Reserved seats: 6
```

This example runs in memory with ordinary SQL and no model. For file-backed databases, view definition changes, or opt-in read-only natural-language queries, see the [experimental SQL preview](/reference/sql-preview/). The [full reservation example](https://github.com/tugrulguner/refpot/blob/v0.1.2/examples/sql_maintenance.py) handles several resources and rejects bookings for missing resources.

## A first database

Use the separate fixed-schema `refpot.Database` and `Row` API to store integer-keyed records directly from Python. Save this program as `first_database.py`:

```python
from pathlib import Path
from tempfile import TemporaryDirectory
from refpot import Database, Row

with TemporaryDirectory() as directory:
    path = Path(directory) / "notes.rp"
    with Database(path) as db:
        db.insert(1, 42, "answer")
        db.update(1, value=43)
        assert db.get(1) == Row(1, 43, "answer")

    with Database(path) as db:
        assert db.get(1) == Row(1, 43, "answer")
```

```sh
python first_database.py
```

This is executable package behavior, not a site simulation. See the [quick start](/package/), [CRUD](/build/crud/), [transactions](/build/transactions/), [persistence](/build/persistence/), and [errors and ownership](/build/errors/) guides.

## Build with RefPot

- [Experimental SQL preview](/reference/sql-preview/): maintained views, transaction rules, optional file-backed storage, and opt-in read-only agent queries. Ordinary SQL needs no model.
- [Fixed-schema Python reference](/reference/api/): records, transactions, and ownership for `refpot.Database` and `Row`. See its [package contract](/package-contract/) for storage and recovery limits.
- [Design direction](/design/) and [roadmap](/project/roadmap/): the engine experiments still ahead. ORM and concurrent access are not shipped.
