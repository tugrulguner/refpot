## A first database

Install RefPot with `python -m pip install refpot`, then save this complete program as `first_database.py`:

```python
from pathlib import Path
from tempfile import TemporaryDirectory
from refpot import Database, Row

with TemporaryDirectory() as directory:
    path = Path(directory) / "notes.rp"
    with Database(path) as db:
        db.insert(1, 42, "answer")
        db.update(1, value=43)
        assert db.get(1) == Row(1, 43, "answer")

    with Database(path) as db:
        assert db.get(1) == Row(1, 43, "answer")
```

```sh
python first_database.py
```

This is executable package behavior, not a site simulation. See the [quick start](/package/), [CRUD](/build/crud/), [transactions](/build/transactions/), [persistence](/build/persistence/), and [errors and ownership](/build/errors/) guides.

## Run the shipped CRUD and transaction examples

The preview supports caller-provided signed-64-bit integer keys and values, UTF-8 text up to 31 encoded bytes, CRUD, and explicit transactions. The parent directory of a database file must already exist. Build prerequisites, ownership, recovery behavior, errors, and limits are in the [package contract](/package-contract/).

From a checkout with a C++17 toolchain, run the literal install and shipped examples:

```sh
uv pip install .
python examples/crud.py
python examples/transactions.py
```

The examples use temporary files, exercise inserts/updates/deletes and commit/rollback, then reopen persisted state. They run the native package; this site does not simulate database execution. The [example sources](https://github.com/tugrulguner/refpot/tree/main/examples) are the executable reference.

## Package contract and qualification

A database is exclusively owned by one process and usable only by its creating thread. Snapshot and WAL recovery are bounded to 64 MiB each. Incomplete unacknowledged tails are discarded; complete transactions with both copies corrupt are rejected; uncertain writes poison the writer. These implementation details do not establish broad recovery or physical power-loss qualification. SQL, ORM, concurrent readers, multiwriter operation, Windows, and existing-format compatibility are not supported.

The six-cell actual-package screen compares public Python calls with prepared SQLite. Three cells remain below 2×, so the overall SQLite target remains unmet. Provenance identifies source revisions represented by wheels labeled 0.1.1; these are not measurements of package artifacts built from 0.1.2 metadata. See the [full package results](/project/package-performance/) and the [reproduction guide](https://github.com/tugrulguner/refpot/tree/main/benchmarks/package-performance). Historical update-harness ratios and reopen losses remain separate evidence.

Read the [exact package contract](/package-contract/), [status and next steps](/status/), [design direction](/design/), [performance qualification method](/performance-method/), and [canonical roadmap](/project/roadmap/). SQL and ORM are design direction, not shipped functionality.

## Historical benchmark findings

<figure class="historical-benchmark"><a href="/refpot-benchmark.png"><img src="/refpot-benchmark.png" alt="Historical random-update experiment: both campaigns passed the scoped service, setup-inclusive and p99 comparison; reopen with full-state validation was slower in all 16 cells." width="960" /></a><figcaption>Historical prototype evidence, not a benchmark of the published Python package. <a href="/project/benchmarks/">Full results, fairness contract, raw evidence and reproduction</a> · <a href="/refpot-benchmark.png">Full-size chart</a> · <a href="/refpot-benchmark.svg">Editable SVG</a>.</figcaption></figure>

The **3.04–5.95× service** and **2.99–5.91× setup-inclusive** results apply only to the historical existing-row update harness in a Linux ARM64 Docker/ext4 VM. This is **not a package claim**. The experiment retained 672 records across two campaigns; reopen with full-state validation remains **16/16 losses**, and earlier failed experiments are preserved. Package performance is unqualified; the broad 2×-over-SQLite objective remains an acceptance target.

Read the [accessible per-cell results and audit](/project/benchmarks/) before citing a ratio. The [performance qualification method](/performance-method/) explains what a future package comparison must establish.
