## Current package preview

The Python `Database` and `Row` interface supports caller-provided signed-64-bit integer keys and values, UTF-8 text up to 31 encoded bytes, CRUD, and explicit transactions. Database paths identify files; the parent directory must already exist. A C++17 toolchain is required for local source installation: `uv pip install .`. No PyPI release is available.

## Current package architecture

<figure class="planned-architecture"><a href="/refpot-package.svg"><img src="/refpot-package.png" alt="Unreleased package preview: Python Database and Row over a native C++ engine. WAL transaction copies are synchronized before memory publication; checkpoint snapshot sync, rename and directory sync happen before log truncation." width="1200" height="760" /></a><figcaption>Unreleased local source-build preview; package qualification remains in progress. <a href="/package-contract/">Full package contract</a> · <a href="/refpot-package.svg">Full-size editable SVG</a>.</figcaption></figure>

The API is thread-affine with exclusive process ownership. SQL, ORM, Windows, concurrent readers, multiwriter operation, existing-format compatibility, and physical power-loss qualification are not claimed. Recovery bounds each snapshot and WAL to 64 MiB.

## Audited experimental result

An [audited random-update experiment](https://github.com/tugrulguner/refpot/tree/main/benchmarks/random-updates) passed the scoped service/setup 2× target in all 16 repeated cells: **3.04–5.95× service** and **2.99–5.91× including setup**, with better tested p99. The repository includes frozen experimental source, 672 raw records and reproduction commands.

<figure class="planned-architecture"><img src="/refpot-benchmark.png" alt="Audited random-update benchmark, both campaigns and the recovery limitation" width="1600" height="1100" /><figcaption>Scoped experimental result only. Full numbers and limitations are in the linked findings.</figcaption></figure>

This is existing-row mutation with atomic receipt tracking against equally batched, tuned SQLite in a Linux ARM64 Docker/ext4 VM—not a supported general database. **Reopen with full-state validation was slower in all 16 cells.** Earlier failed workloads remain documented.
